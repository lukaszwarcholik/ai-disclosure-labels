Mark images as AI-generated and show a visible disclosure label everywhere they appear.

== Description ==

Pick one option on an image - generated by AI, or a real image modified using AI - and every place that image shows up on your site carries the matching disclosure label - featured images, images in content, galleries, images your theme renders through the standard WordPress functions.

The mark is stored on the **attachment**, not on the post. Mark a file once and it stays marked wherever it is reused. Deleting the plugin leaves those marks on your images, so you never come back to a media library that needs marking from scratch; a setting removes them on uninstall if you want a clean slate.

**Why this exists**

The EU AI Act (Article 50) has applied since 2 August 2026. Among other things, anyone who publishes AI-generated or AI-manipulated images of real people, objects, places or events in a way that could pass for authentic has to disclose it visibly. This plugin does not decide which of your images need that - you do. It makes publishing the disclosure a single checkbox instead of a manual caption you will forget on the fifth post.

**Two kinds of disclosure**

A fully synthetic image and a real photograph an AI has altered both need disclosing, but they are not the same claim, and a reader can tell the difference. So each gets its own label text, which you control.

**What it does**

* A *Generated by AI* / *Modified using AI* picker in the Media Library and in the media modal.
* A control directly under the featured image in the block editor, naming the file it marks, saved instantly.
* An *AI* column in the media library list view, so you can see what is marked.
* Full caption under the image on single posts and pages; a compact badge on thumbnails, in listings and archives, so the disclosure is there at first exposure, not only after a click. The label sits directly under the image, above any caption the theme adds.
* Label text and badge text per kind, position (under the image or in any of its four corners), style (plain text, dark, white or translucent), size, opacity and where to show it - all configurable.
* No build step, no external requests, no tracking, no database tables.

**Where it reaches automatically**

* Featured images (`post_thumbnail_html`).
* Images rendered with `wp_get_attachment_image()` - most themes, most custom loops.
* Core image, gallery and media-and-text blocks.
* Images in post content, including content written in the classic editor or printed by a shortcode.
* Optionally, every other image on the page - see below.

**Images the theme prints itself (ACF, sliders, page builders)**

A template that prints `<img src="<?php echo $field['url']; ?>">` straight from an ACF field passes through no WordPress filter at all, so there is nothing to hook. Switch on *Images the theme prints itself* in the settings and the finished page is scanned instead.

It is not a general image parser: the plugin already knows which attachments you marked - usually a handful - so it builds a file-name list for those files only (original plus every registered size) and looks for exactly those names. No database query per image, and because the match is on the file name, a CDN or an offloaded upload path still matches. `<picture>` elements from WebP converters are handled as a whole.

If you would rather not have the page scanned, put the label in the template yourself:

`<?php aidl_label( $attachment_id ); ?>`

or in content: `[aidl_disclosure id="123"]`

**Filters**

* `aidl_label_text` - ( $text, $attachment_id, $variant, $mode )
* `aidl_badge_text` - ( $text, $attachment_id, $mode )

**Languages**

English (source) and Polish included.

== Installation ==

1. Plugins -> Add New -> Upload Plugin, or install from the plugin directory.
2. Activate.
3. Settings -> Lucjan AI Image Disclosure to set the label text (optional - the defaults work).
4. Open an image in the Media Library and set *AI disclosure* to *Generated by AI* or *Modified using AI*.

== Frequently Asked Questions ==

= Does it detect AI images by itself? =

No, and on purpose. Detection is guesswork: run a generated image through an editor and every detector goes quiet. You know which of your images came out of a generator - the plugin makes marking them a checkbox.

= Is a note in the footer enough? =

That is a question for your lawyer, not for a plugin. The transparency duty in the AI Act is about the disclosure being clear to the person looking at the content; a line in the footer of a site is not attached to any particular image. Per-image labelling is the safer reading.

= Where does the label go? =

By default the plugin decides per image: a caption under large images, a compact badge on thumbnails - because a caption needs room to read and a thumbnail has none. You can override that and put it under the image everywhere, or in any of the four corners on it, with a plain, dark, white or translucent style.

= Does it slow the site down? =

One meta read per labelled image and a handful of inline CSS rules. No scripts on the front end.

= Will it work with a page builder? =

Yes, with *Images the theme prints itself* switched on. Without it, the plugin reaches anything rendered through the standard WordPress image functions and core blocks, which covers most themes but not builders that output their own markup.

= Does the page scan slow things down? =

It is one pass over the output of a page you are already rendering, and it only runs when you have at least one marked image. The file-name list is cached for a day and rebuilt when you mark or unmark an image. If no image on your site needs it, leave the option off.

= What happens when I uninstall it? =

The settings go. The marks on your images stay, so deactivating the plugin for an afternoon does not mean re-marking three hundred images afterwards - reinstall it and everything is marked as before. If you would rather leave nothing behind, switch on *Also delete the image marks when the plugin is deleted* in the settings before you delete the plugin.

== Changelog ==

= 1.5.0 =
* New name. The previous one was close enough to another plugin in the directory to be confusing.
* The shortcode is now `[aidl_disclosure]`. The old `[ai_disclosure]` is gone - rename it in any content that used it.
* Translations now come from translate.wordpress.org instead of shipping inside the plugin.

= 1.4.0 =
* The mark moved out of its own sidebar panel and sits directly under the featured image, where you are actually looking when you choose the picture.
* It names the file it marks. A panel between Categories and Tags reads as a setting of the post; it never was one, and an image used by three posts changes in all three. The file name says that faster than a sentence under the control.

= 1.3.0 =
* Deleting the plugin no longer deletes the marks on your images. A mark is something you said about your own photograph, not plugin bookkeeping, and nobody should come back from a week without the plugin to a media library that needs re-marking. The settings are still removed.
* New setting: *Also delete the image marks when the plugin is deleted*, off by default, for anyone who does want a clean slate.

= 1.2.0 =
* Label position: automatic, always under the image, or any of the four corners on it.
* Label style: plain text, dark background, white background, or translucent with a blur.
* Opacity now applies to plain text only. Fading a pill fades its background with it, and a half-transparent box over a photograph is exactly where a disclosure stops being legible.
* A plain-text label placed on an image gets a text shadow, so it stays readable over a photograph.

= 1.1.0 =
* Two kinds of mark instead of one checkbox: *Generated by AI* and *Modified using AI*, each with its own label and badge text. Images marked in 1.0 keep their label and are read as generated.
* `aidl_label_text` and `aidl_badge_text` now receive the mode as their last argument.
* The label carries an `aidl-label--generated` or `aidl-label--modified` class, so the two can be styled apart.

= 1.0.1 =
* The label is now attached to the image itself, never around the container the theme built. A theme that returns a whole `<figure>` for the featured image used to get the label below the caption, detached from the picture - and lost any styling written as `.parent > figure`.
* Small sizes always get the compact badge, even on a single post: a full caption under a 150px sidebar thumbnail read as a broken layout.

= 1.0.0 =
* First release.
* Marking in the Media Library and in the block editor.
* Labels on featured images, images rendered by theme functions, blocks, and images in post content from the classic editor.
* Optional scan of the finished page for images a theme prints itself.
* `aidl_label()` template function and `[ai_disclosure]` shortcode.
* English and Polish.
